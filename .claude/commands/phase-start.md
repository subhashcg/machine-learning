---
description: Orient at the start of a phase — goal, steps, and what the project demands
argument-hint: "[phase number, e.g. 2]"
---

Load the `tutor` skill, then start phase $ARGUMENTS.

1. Read that phase from `CURRICULUM.md`.
2. Confirm the previous phase's steps are all merged into `main`. Say plainly if
   any are not.
3. Orient the learner, briefly:
   - the phase goal, in your words not a quote
   - the steps it contains, and why they are in that order
   - what the phase project will demand, so they know what they are building toward
   - anything from earlier phases this one finally pays off
4. Name any new dependencies the phase needs, but do not install them yet — they
   belong to the step that first uses them.

Do not start a step. End by naming the first one and waiting.
